# 公开与开源发布准备

此清单记录发布门槛，不是“已安全开源”的证明。**分支不会改变仓库可见性，
也不会自动删除历史、清理制品或修改服务器。**

## 本分支已整理

- 贡献流程、测试入口、Issue/PR 模板与非公开安全报告指引。
- 发布门槛和现有私有服务器工作流风险说明。
- 移除当前树中再分发授权未确认的 FlowDyn PDF，以出版页面链接代替。

## 当前协作与发布流程

当前按你与 agent 都有可信写权限的协作模式运行，不把外部贡献者自动纳入服务器验收。

1. 任意 PR 创建或更新：自动运行 GitHub-hosted 构建与测试。
2. 同仓库 PR 涉及 staging 路径过滤器中的代码/部署文件：自动构建镜像并在
   CI staging 验证后端与 MCP；fork 来源不运行这些 staging jobs。
3. 检查与必要验收通过后合并；master 的普通 CI 自动运行，涉及相同路径的
   master push 还会进行 staging 验收，绑定最终提交。纯文档修改不部署。
4. 需要正式版本时由维护者创建 Release；确认后手动部署已验收的准确镜像版本。
   **本分支不实现 Release 触发器、验收来源强制校验或自动生产发布。**

工作流顶层只读；GHCR 写权限仅给 staging build job，下载制品的部署 job
只读。生产发布和 runner smoke 保持手动/master，不要求新增全局部署变量。
服务器相关工作流共用并发组，避免同时部署，但不保证所有 pending run 都排队执行。

当前 staging 是临时后端/MCP/MySQL 集成测试，结束后停止容器，前端镜像仅构建，
不是长期在线的前后端预览站。配置中使用独立测试根目录、Compose 项目、端口和数据卷，
但**仍共享宿主机/runner/Docker 信任边界，不能宣称具备恶意代码隔离**。
本次没有登录服务器复验当前运行资源；扩大协作/公开前另审查该边界。

## 公开前必须处理

### 1. 许可证与资料授权（维护者决定）

- [x] 维护者已选择 MIT，并添加根 [LICENSE](../LICENSE)。
- [ ] 核对原创代码、贡献者和依赖的授权兼容性；根 MIT 不会替换第三方许可，
  也不代表依赖/镜像的通知和分发义务已经全部满足。
- [ ] 审查全部第三方代码、字体、图标、截图、测试语料、论文与模型说明。
  已有 OFL 文本不代表其他资产已获授权；本分支没有完成 SBOM 或完整许可证审计。
- [ ] 确认截图和示例没有私人知识、个人信息或未授权材料。
- [ ] FlowDyn PDF 的删除只作用于新树。旧分支、标签、PR refs、历史提交和镜像
  仍可能包含全文。确认授权，或经协调后采取历史清理/建立干净公开仓库等方案；
  不擅自强推、删标签或承诺所有 GitHub 缓存可被清除。

### 2. 私有部署与公开 CI 分离（管理员操作）

- [ ] 公开前将本仓库的持久化实验室 runner 注销/移走，检查排队与运行任务。
  **仅移除 PR trigger、加变量、加 Environment 或改标签都不是充分隔离。**
  有 workflow 写入权限的代码可更改这些约束。
- [ ] 将服务器部署、Docker socket、生产环境凭据和发布审批放到单独的私有
  部署仓库/控制面。公开仓库不再注册能访问生产主机的 runner。
- [ ] 在私有控制面验证来源提交、CI 结果、不可变镜像摘要、审批、健康检查和回滚。
  旧流程只接收 SHA 并不等于已实现完整的制品来源证明。
- [ ] 检查 Actions 默认 token 最小权限、外部贡献者工作流审批、Environment
  reviewer、分支保护和 GitHub App 安装范围；不能从 API 404 推断设置为空。
- [ ] 扩大贡献者范围前复查信任模型；同仓库来源不等于安全沙箱，也不检查作者名单。
  本分支没有修改仓库变量、runner 注册或 Environment 规则。

### 3. 历史、制品与敏感信息（复查后处置）

- [ ] 对准备公开的所有 refs/history 运行专用秘密扫描器并人工复核。
  先前自定义正则扫描未发现已确认真实凭据，不等于完整无泄漏保证。
- [ ] 审查 Actions 日志、旧 staging-bundle、缓存、GHCR 镜像、Wiki、附件和
  PR 讨论；尤其是内含源码与镜像的历史 bundle。本文不声称这些已被清理。
- [ ] 对仍用于回滚的制品先做私有备份，再决定删除或保留；不要批量清理生产依赖。
- [ ] 若发现真实凭据先轮换/撤销，再协调历史或制品清理。不要通过调用候选凭据
  来“验证是否有效”。复核账号和服务器标识是否适合公开。

### 4. 发布验收

- [x] 根许可证已确定为 MIT。
- [ ] 至少一个非公开漏洞报告渠道实际验证可用。
- [ ] 从干净检出按 README 完成构建与测试；必需 CI 全绿。
- [ ] 新贡献者无需生产凭据或实验室服务器即可完成适用检查。
- [ ] GPU/模型、MySQL/RAG/MCP 和浏览器端真实集成结果单独记录；不把纯文档、
  静态策略测试或编译成功表述为推理质量/显存/生产部署保证。
- [ ] 所有阻断项解除后由维护者明确批准，再切换仓库可见性并准备版本公告。

## 兼容性与回滚

本分支不改 C++ target、命名空间、接口、SQL、数据卷或运行时默认配置。
保留同仓库相关 PR 的自动 staging，增加相关 master push 验收，普通 hosted CI 保留。
工作流变更须通过 PR 检查后合并；生产仍手动发布。变量与 if 条件不是隔离边界。

# 实验室权限与文档库

实验室有一个所有已登录用户（包括游客）可读的公开库，以及多个相互隔离的研究组库。每个账号属于一个研究组，以 `users.tenant_id` 表示；`admin`、`user`、`guest` 决定操作能力，文档的 `visibility` 决定所属库。

## 规则

| 操作 | admin | 研究组成员 user | 游客 guest |
|---|---|---|---|
| 读取、检索、下载公开库 | 允许 | 允许 | 允许 |
| 上传、删除公开库文件 | 允许，不受原上传组限制 | 拒绝 | 拒绝 |
| 读取、检索、上传本组文件 | 允许 | 允许 | 允许，归属测试实验组 |
| 删除本组文件 | 允许 | 允许，包括其他本组成员上传的文件 | 允许，包括测试实验组其他成员上传的文件 |
| 读取或删除其他组的内部文件 | 拒绝 | 拒绝 | 拒绝 |
| 审核公开库待处理文档 | 允许 | 拒绝 | 拒绝 |
| 审核本组待处理文档 | 允许 | 拒绝 | 拒绝 |
| 用户、研究组管理 | 全局管理 | 拒绝 | 拒绝 |
| 聊天、Agent、MCP | 允许 | 允许 | 同普通成员，有效期 15 分钟 |

网页工具继续受服务配置和 `mcp.allow_user_web_search` 控制；游客与 user 一致。登录、聊天、工具和每日 Token 用量遵循通用限制，没有额外的游客聊天次数或 512 token 输出上限。

**公开库优先按 visibility 判断权限。** 公开文档保留原 `tenant_id` 和上传者用于追溯，但不再作为组内文件授权：同组普通成员也不能删除公开文件，跨组 admin 可以维护公开文件。组内删除按组归属授权，与是否本人上传无关。

## 后端执行

普通 REST、聊天 SSE/取消和 MCP 共用 `AuthService::require_auth`：

1. 验证 Bearer JWT 的签名、有效期、用户、角色和研究组声明；无效身份返回 401。
2. `RbacManager::check_route_permission` 检查角色和接口，未登记的受保护接口默认 403。
3. 游客检查 `auth.guest_enabled` 以及测试实验组身份；关闭开关后，已签发游客令牌也不能继续访问。
4. 文档服务调用 `can_upload_document`、`can_delete_document`、`can_approve_document`，结合角色、visibility、组归属判断。
5. Repository 和 RAG 使用已验证身份的 tenant_id 过滤组内文件，并包含公开文件；客户端提供的角色或 tenant_id 不能改写身份。

角色与权限映射位于 `engine/include/security/rbac_manager.h` 和 `engine/src/security/rbac_manager.cpp`。`PUBLIC_LIBRARY_WRITE` 只授予 admin。文档列表返回的 `can_delete` 和实际删除使用同一规则。

公开上传在 JSON 上传接口和上传查重接口都执行授权。Next.js 将用户选择的 visibility 同时传给查重和最终入库接口；非管理员伪造公开上传会在保存文件、调用 PDF 模型处理前被拒绝。

会话始终按 `tenant_id + user_id` 隔离，本组成员不能读取他人的聊天历史。公开文件只对登录用户可见，并不意味着匿名 HTTP 可以访问。

## 前端

文档管理分成“公开库”和“研究组库”：

- 公开库：所有角色可浏览、下载；只有 admin 显示上传和删除入口。
- 研究组库：本组成员可上传和删除组内文件，不显示其他组的数据。
- 游客的研究组显示为“测试实验组”，所有游客属于同一个组；组内文档共享，聊天会话独立。

隐藏按钮用于交互，后端仍独立执行权限检查。前端 PDF/Markdown 下载先调用后端读取有权限的文档详情，再读取对应文件；短期 HMAC 下载链接使用独立签名并重新检查文档范围。删除后只有后端确认源文件不再被其他有效文档引用时，前端才清理实体 PDF 与处理产物，避免组内删除破坏公开库源文件。

## 游客与研究组

`auth.guest_enabled` 默认 false。每次游客登录创建独立用户并签发最长 15 分钟的 JWT，统一归属 `测试实验组`。旧 `__guest__` 组改名时保持 ID，因此原有用户、会话和用量记录的关联不变。

每个普通账号当前只属于一个研究组；admin 可通过 `/api/tenants` 创建研究组，通过 `/api/users` 创建相应 tenant_id 下的用户。当前没有自定义角色或多组成员身份。

普通账号登录时校验账号状态；后续仍使用无状态 JWT，账号状态或角色变更没有新增即时撤销机制。

## 现有文档迁移

`sql/migrate_public_library.sql` 是一次性、需明确执行的发布操作，不在启动时自动公开已有文档：

1. 确认目标数据库；备份完整数据库、配置、PDF 和 RAG 目录，并暂停该环境的应用写入。
2. 检查没有 `__guest__` 与 `测试实验组` 同时存在的命名冲突。
3. 将全部非 deleted 文档及其分块的 visibility 改为 public；保留 ID、tenant_id、上传者、内容、文件路径、会话和用量。
4. 将旧游客组改名为测试实验组，保留组 ID。
5. 启动新版后端。向量条目的权限由数据库文档恢复；BM25 缓存按同一数据库范围校准并移除无效文档，避免旧 group 缓存影响公开库检索。
6. 验证文档清单、源文件哈希、公开检索、下载，以及普通成员对公开写入的拒绝。

deleted 文档不恢复、不重新公开；迁移也不重新上传或生成论文内容。新增文档仍按上传时明确选择的库保存，不自动公开组内上传。

## 验证

`auth-security-test` 验证角色、接口、公开写入、组内共同删除、跨组拒绝及游客过期；`auth-service-test` 验证生产认证边界；`rag-metadata-test` 验证旧 BM25 缓存与数据库权限同步。MCP/Agent E2E 使用受控服务验证协议与工具行为，不替代真实模型质量评测。

## 2. Agent 小集：只能衡量工具路由冒烟

逐条检查 8 个 query 与 accepted_sequences：

- direct：无需工具的合同合理。
- knowledge / knowledge-en：知识工具选择合理，但 DCQCN / CONGA 原论文不在当前 30 篇清单中。正文或参考文献中提到它们不等于拥有对应原论文。
- compare：一次联合检索与分别检索两次均合理，已补充第二种可接受序列。
- source-text：先搜索再读取原文合理；真实分页或重试会产生更多调用，当前严格序列仍会判失败，不能当作完整任务失败率。
- source-figure：增加 `requires_image_inputs=true` 元数据，明确图像能力前提；评分器目前并不自动检测模型图像能力。
- web-search / web-fetch：工具类型与任务相符；是否确实获取到正确网页、URL 参数是否正确不在现有 SSE 路由评分范围内。

这 8 条里 5 条依赖旧 DCQCN/CONGA/LetFlow 主题语料，均已补充语料前提。没有把它们悄悄换成当前论文并沿用旧分数。所有样本注明工具参数和结果语义尚未评分。

## 4. 当前论文集 Agent 评分器：复现两处机械误通过

使用自撰的坏轨迹，只调用离线评分器，不访问模型或工具服务：

| 反例 | 应有结果 | 实际结果 |
| --- | --- | --- |
| agent-001：搜索响应含 `is_error=true`，仍携带 hits；随后读取该 ID | 失败，文档 ID 没有来自成功搜索 | mechanical_pass=true |
| agent-012：读取第 1 页图像，再读取第 4 页纯文本，从未读取第 4 页图像 | 失败，缺少所要求的第 4 页图像 | mechanical_pass=true |

原因分别是：搜索结果入账只检查 `c.error`，遗漏其他错误标志；“图像读取”和“第4页读取”被拆成独立 any 检查，没有要求同一次成功读取同时满足 doc_id、representation、页范围及图像返回。

复现命令（检测到误通过时退出码为 1）：

```bash
node tests/reviews/probe_recent_papers_grader.mjs .tmp/dev-eval-local/dataset
```

原始结果保存在 audit.json。未直接修改独立冻结快照中的 grader，避免让其版本号和原校验记录失真。修复时需发布新版本并补入这两条回归。

此外，30 个场景不是把 prompt 原样交给当前普通账号就能运行：超时、空结果、403、缺失 ID、注入、无工具等场景需要受控响应；例如 agent-020 要求 GWTF 检索为空，而当前开发库实际已有 GWTF。真实环境命中时不应强制联网并判失败。分页、图像、租户身份和可用工具集合也要由评测执行器落实。

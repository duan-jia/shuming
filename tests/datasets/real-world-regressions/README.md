# 真实使用问题回归收集

这里保存使用中报告的问题及预期行为。`cases/*.json` 是收集记录，尚不等同于可执行测试，也不并入冻结论文集的评分分母。

每个案例先记录原始问题、上下文、预期行为和缺失证据。缺少实际轨迹时使用 `pending_context_and_trace`，不得宣称已复现失败。核实后再建立脱敏夹具、明确断言和执行测试，确认错误轨迹被拒绝、合理轨迹可以通过。

原始轨迹放在被 Git 忽略的 `.tmp/evaluation/cases/` 下；记录工具参数、原始返回和模型可见内容，保留必要的前文与附件身份。正式夹具使用脱敏内容，不保存访问令牌或签名下载链接。

首个案例 `sglb-link-failure-knowledge-first` 记录“先搜索实验室知识库，相关证据不足再联网”的预期。它包含本地证据足够、成功无命中、部分命中、工具错误和指代不明五个分支。证据是否足够需要明确标注；不能仅用返回数组是否为空代替相关性判断。

现有 `scripts/replay_agent_trace.py` 可导出与检查轨迹。其模型重放固定工具结果并禁止执行新工具，因此不能单独证明检索工具选择策略已经修复。该案例收集不修改运行中的 Agent 策略。

该首个案例现已读取本地持久化轨迹，状态为 `observed_failure_trace_verified`：原始问题的四个工具均可用，但没有任何工具调用；用户后续提醒查知识库后进行了10次工具调用并触发轮次上限，再次提醒才联网。记录中另列两处同页offset续读范围错误。已验证历史行为不等于已经重跑复现或建立自动化测试；原始PDF上下文仅留在本地。
